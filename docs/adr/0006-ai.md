# ADR-0006: On-device OCR + Claude in Microsoft Foundry

**Status:** Accepted — to be validated by the M3 spike · 2026-11-05

## Context
AI features: register a bean by photographing its label, personalised starting recipes, and a dial-in assistant. Everything should run on Azure, cost must stay low and the app is offline-first.

## Decision
- **On-device OCR** with Apple's Vision framework (text recognition) via .NET for iOS bindings. Free, fast, works offline.
- **Claude in Microsoft Foundry** (Messages API on the Foundry resource endpoint) for:
  - structured extraction of label text into a `BeanDraft` JSON schema (structured outputs), sending the image only when OCR confidence is low;
  - starting recipes and dial-in suggestions as structured `RecipeSuggestion` output.
- Called from `Dialed.Api` through `Dialed.AI` using the official Anthropic C# SDK (with its Foundry package) or plain `HttpClient` — decided in the spike.
- **Model IDs are configuration**: a small/fast model for extraction, a stronger model for suggestions.
- **Deterministic rule-based fallback** in `Dialed.Domain` for offline dial-in suggestions.
- **Prompt versioning**, a **golden test set** of real labels, **per-user quotas**, token/cost telemetry, and **no personal data** in prompts.

See [architecture.md §5](../architecture.md#5-ai).

## Consequences
- Billing via Azure Marketplace for Claude; budget alerts required.
- Foundry offers Global Standard and US data-zone deployments for Claude, no EU data zone listed → fine for a private beta, revisit for a public EU release.
- Foundry has no built-in content filter for Claude deployments; inputs are coffee data, outputs are schema-validated.

## Alternatives considered
- **Azure OpenAI (GPT models)** with the same split.
- **Cloud-only vision** (send every photo): simpler pipeline, higher cost per scan and no offline OCR.
