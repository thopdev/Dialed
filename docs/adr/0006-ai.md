# ADR-0006: Claude in Microsoft Foundry for label scanning and recipe help

**Status:** Accepted — to be validated by the M3 spike · 2026-11-05 (revised the same day: on-device OCR dropped because the client is a PWA, see ADR-0009)

## Context
AI features: register a bean by photographing its label, personalised starting recipes, and a dial-in assistant. Everything should run on Azure, cost must stay low and the app is offline-first. The client is a browser app on iPhone/iPad, so Apple's on-device text recognition (Vision) is not available.

## Decision
- **Label scan:** the app resizes the photo in the browser (about 1.5–2 megapixels, JPEG) and uploads it; the API sends the image to **Claude in Microsoft Foundry** (Messages API on the Foundry resource endpoint) with **structured outputs** into a `BeanDraft` JSON schema with per-field confidence.
- **Recipe help:** starting recipes and dial-in suggestions as structured `RecipeSuggestion` output.
- Called from `Dialed.Api` through `Dialed.AI` using the official Anthropic C# SDK (with its Foundry package) or plain `HttpClient` — decided in the spike.
- **Model IDs are configuration**: a small/fast model for extraction, a stronger model for suggestions.
- **Offline:** a scan is stored as a pending `LabelScan` and processed when back online; dial-in suggestions fall back to **deterministic rules** in `Dialed.Domain`.
- **Prompt versioning**, a **golden test set** of real labels, **per-user quotas**, token/cost telemetry, and **no personal data** in prompts.

See [architecture.md §5](../architecture.md#5-ai).

## Consequences
- Simpler pipeline than OCR + text extraction; slightly more tokens per scan (images), kept in check by resizing and quotas.
- Billing via Azure Marketplace for Claude; budget alerts required.
- Foundry offers Global Standard and US data-zone deployments for Claude, no EU data zone listed → fine for a private beta, revisit for a public EU release.
- Foundry has no built-in content filter for Claude deployments; inputs are coffee data/photos, outputs are schema-validated.
- A future MAUI host could add on-device OCR again behind the same API.

## Alternatives considered
- **In-browser OCR (Tesseract.js) + text to Claude**: fewer tokens, but a large download and weaker recognition of stylised labels.
- **Azure OpenAI (GPT models)** with the same design.
